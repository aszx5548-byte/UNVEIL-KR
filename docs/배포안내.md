# UNVEIL 홈페이지 배포 안내

## 이 프로젝트가 만들어내는 것

`npm run build` 를 돌리면 `dist/` 폴더 하나가 나오고, 그 안에 **사이트 전체**가 들어갑니다.

```
dist/
├── index.html          홈페이지
├── assets/             React 코드와 CSS (파일명에 해시가 붙음)
├── saju/index.html     사주 음양오행 앱
├── zodiac/index.html   별자리 운세 앱
├── birthstone/index.html  탄생석 추천 앱
├── images/             사진 9장
├── favicon.svg .ico    탭 아이콘
└── manifest.json  sw.js
```

서버가 필요 없는 **순수 정적 사이트**입니다. 정적 파일을 서빙할 수 있는 곳이면 어디든 올라갑니다.

---

## 방법 1 — 구글 AI Studio (Cloud Run)

### 준비

GitHub 저장소가 필요합니다. 이 폴더는 이미 git 저장소로 초기화되어 있고 첫 커밋이 되어 있습니다.

```bash
git remote add origin https://github.com/사용자명/저장소명.git
git push -u origin main
```

### 배포

1. [aistudio.google.com](https://aistudio.google.com) → **Build** 모드
2. 프롬프트 입력창의 **Add files** → **Import a project from GitHub**
3. 위에서 만든 저장소 선택
4. **Publish** 버튼 → Cloud Run 주소가 나옵니다

무료로 앱 2개까지 배포할 수 있고 결제수단 등록이 필요 없습니다.

### 배포 후 반드시 확인할 것

AI Studio 는 AI 가 만든 앱을 다루는 환경이라, 손으로 쓴 정적 HTML 이
그대로 살아남는지 문서에 명시되어 있지 않습니다. 아래를 눈으로 확인하세요.

- [ ] 첫 화면에 3개 카드가 보이는가
- [ ] **사주 카드를 누르면 사주 앱이 뜨는가** ← 가장 중요
- [ ] 별자리 · 탄생석 카드도 각각 앱으로 가는가
- [ ] 앱에서 "UNVEIL 홈" 버튼으로 돌아오는가
- [ ] 사진 9장이 다 뜨는가
- [ ] 탭에 골드 스파클 아이콘이 뜨는가

3개 앱이 안 뜬다면 `public/` 폴더가 빌드 결과에 복사되지 않은 것입니다.
그 경우 방법 2로 가는 것이 빠릅니다.

### 알아둘 점

Cloud Run 배포는 **HTTP 응답 헤더를 설정할 수 없습니다.**
그래서 핵심 보안 정책(CSP)은 각 HTML 의 `<head>` 안에 `meta` 태그로 넣어두었습니다.
어디에 올려도 이 정책은 따라갑니다.

다만 헤더로만 전달 가능한 아래 항목은 Cloud Run 에서 적용되지 않습니다.

| 항목 | 없으면 |
|---|---|
| `X-Frame-Options` / `frame-ancestors` | 다른 사이트가 iframe 으로 감싸 클릭을 가로챌 수 있음 |
| `Strict-Transport-Security` | 첫 접속 시 HTTPS 강제가 약해짐 |
| `Permissions-Policy` | 카메라 · 마이크 등 권한 차단이 없어짐 |
| `Cache-Control` | 캐시 전략이 호스팅 기본값을 따름 |

사이트가 망가지는 문제는 아니고, 방어층이 얇아지는 정도입니다.

## 방법 2 — Netlify

`netlify.toml` 이 이미 들어 있어 빌드 설정을 따로 입력할 필요가 없습니다.
보안 헤더 7종과 캐시 설정이 모두 적용됩니다.

1. [app.netlify.com](https://app.netlify.com) → 사이트 선택 (또는 새로 생성)
2. Site configuration → Build & deploy → **Link to a Git repository**
3. 위 GitHub 저장소 연결

**무료 한도 주의** — 2026년부터 크레딧 방식입니다.

| 항목 | 소모 |
|---|---|
| 월 무료 한도 | 300 크레딧 (계정 전체 공유) |
| 프로덕션 배포 1회 | 15 크레딧 → **월 20회** |
| 트래픽 1GB | 20 크레딧 |

한도를 넘기면 **계정의 모든 사이트가 다음 결제주기까지 정지**되고
방문자에게 "Site not available" 이 뜹니다.
수정할 때마다 배포하지 말고, 로컬에서 확인한 뒤 몰아서 올리세요.

## 방법 3 — Cloudflare Pages

트래픽이 늘면 여기가 가장 여유롭습니다. `public/_headers` 가 이미 들어 있어
보안 헤더가 그대로 적용됩니다.

| 항목 | 무료 한도 |
|---|---|
| 트래픽 | **무제한** |
| 빌드 | 월 500회 |
| 저장 용량 | 10GB |

빌드 설정: 명령 `npm run build`, 출력 디렉터리 `dist`

## 로컬에서 확인하기

Node.js 가 설치되어 있어야 합니다.

```bash
npm install
npm run dev        # 개발 서버
npm run build      # 배포용 빌드 → dist/
npm run typecheck  # 타입 검사 (빌드와 분리되어 있음)
```

`npm run build` 는 일부러 `vite build` 만 실행합니다.
타입 오류 하나로 배포 빌드가 통째로 실패하는 것을 막기 위해서입니다.
타입 검사는 `npm run typecheck` 로 따로 돌리세요.

**`npm install` 을 한 번 돌리면 `package-lock.json` 이 생깁니다. 반드시 커밋하세요.**
이 파일이 없으면 빌드할 때마다 의존성 최신 버전을 새로 받아,
어느 날 갑자기 빌드가 깨질 수 있습니다.

## 배포 주소가 정해지면 해야 할 것

### 1. 공유 썸네일 (중요)

`index.html` 의 이 줄을 절대주소로 바꾸세요.

```html
<meta property="og:image" content="/images/hero-bracelet.webp" />
```
↓
```html
<meta property="og:image" content="https://실제주소/images/hero-bracelet.webp" />
```

지금은 상대경로라 **카카오톡 · 인스타로 공유할 때 썸네일이 안 뜹니다.**
사주 앱에 결과 공유 기능이 있어 카톡 유입이 주 경로일 텐데, 여기서 손해를 봅니다.

### 2. 기존 Netlify 사이트 정리

`Desktop\UNVEIL-기존사이트-정리용\` 폴더의 `NEW_SITE` 값을 새 주소로 바꾼 뒤,
`vermillion-nougat`(별자리) · `friendly-starburst`(탄생석) 두 사이트에 올리세요.
옛 주소로 들어온 방문자를 새 사이트로 보내고, 기기에 남은 서비스워커를 정리합니다.
1~2주 뒤에 그 사이트들을 삭제하면 됩니다.

### 3. 남은 미확정 항목

`src/data.ts` 에서 고칩니다.

- 상품별 스마트스토어 상세 URL 6곳 (지금은 전부 스토어 메인으로 연결)
- 푸터의 이용약관 · 개인정보처리방침 · 배송/교환/반품 · 고객문의 4곳
  (`href: null` 이면 "준비 중" 안내가 뜹니다. 주소를 넣으면 링크가 됩니다)
